Local harness routing for coding agents

One router for the coding harnesses you already use.

harness-router gives agents a single local interface for Claude Code, Codex, Cursor, Antigravity, and OpenAI-compatible endpoints. It routes by task fit, route readiness, billing policy, safety profile, workspace policy, and your configured priority.

The problem is route choice, not agent hype.

Coding agents are not interchangeable. A bug fix, an architecture review, a long-context inspection, and a local endpoint test have different best routes.

Billing explicit

Block paid or unknown-paid routes until the config explicitly allows them.

Health aware

Use availability, auth, quota state, and circuit breakers before sending work.

Small surface

Expose a routing tool, an async job wrapper, two status resources, and one OpenAI-compatible REST route.

Endpoint modes

Route directly to OpenAI-compatible local HTTP endpoints, or let supported harnesses use local providers natively.

Workspace control

Use shared, locked, copied, or git-worktree agent workspaces depending on the workflow.

Configure is the product entrypoint.

The setup flow detects harnesses, verifies route readiness, classifies billing, chooses safety and model priority, writes config, and connects the agents you want to use with the router.

  1. Detect Claude Code, Codex, Cursor, Antigravity, and configured HTTP/local endpoints.
  2. Verify harness availability and auth without spending quota where possible.
  3. Choose billing policy, endpoint mode, safety profile, workspace policy, and routed harnesses.
  4. Write config and connect MCP agents or print snippets.

npm install -g harness-router

Two transports, one router core.

MCP is the agent-facing interface. REST exists for generic tools that already speak OpenAI-style chat completions.

MCP

Tools: code, job, and usage

Resources: harness-router://status and status.json

REST

POST: /v1/chat/completions

GET: /v1/status

Local endpoints

Direct: Ollama, LM Studio, vLLM, LiteLLM

Native: Codex with ollama or lmstudio

HTTP MCP

POST: /mcp

Protected by the same bearer token as /v1/*.

Install and run.

Node 24 is the target runtime. The default command starts stdio MCP for local agent clients. `serve` starts HTTP MCP and the REST API.

commands v0.4.0 
npm install -g harness-router
harness-router
harness-router serve --port 3333
harness-router auth show

How it differs from agent CLIs and smart routers.

harness-router is deliberately narrow. It does not replace a coding agent and it does not claim benchmarked cost reduction yet.

Category What it does What it does not claim
Agent CLIs Delegates to Claude Code, Codex, Cursor, Antigravity, or HTTP endpoints. It is not a replacement coding agent.
Smart routers Uses task hints, readiness, billing policy, safety, workspace policy, quota, tiers, and configured priority. It does not advertise unmeasured token savings.
Agent protocols Exposes MCP and OpenAI-compatible REST locally. A2A and broader orchestration are out of scope for v0.4.0.

FAQ

Short answers for release-readiness questions.

Why stdio MCP?

It is the simplest local agent integration. Use `serve` when HTTP is needed.

Why auth for local HTTP?

The server can dispatch coding work. Bearer auth avoids accidental local exposure.

Why a small MCP surface?

`code` is the routing API. `job` exists only for slow async runs that need inspection later.

Are isolated workspaces sandboxes?

They protect project state and review flow. Host-level containment still belongs to the downstream harness or OS sandbox.
