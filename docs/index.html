Route coding tasks to the right agent.

harness-router gives your orchestrating agent one local interface to Claude Code, Codex, Cursor, Antigravity, and OpenAI-compatible endpoints. Tasks route by task fit, live quota, billing policy, and safety profile. Whole tasks to whole agents. No proxying, no interception.

Get started

How it works

You have multiple coding agents installed (Claude Code, Codex, Cursor, etc.). Each has different strengths: Codex excels at test-driven execution, Claude at architecture and extended thinking, Cursor at editor-aware context. harness-router picks the best one for each task and delegates through its official CLI interface.

You get the power of all your subscriptions without manually switching between them. Tasks route based on:

Task type

Execute, plan, review — each has different best agents.

Billing policy

Metered API routes are blocked until you opt-in per route.

Live quota

Prefer routes with available quota; skip those rate-limited.

Safety profile

read_only, workspace_edit, full_auto — agent capability gates.

Install and run

harness-router is a Node.js ≥24 CLI. One command to set up:

npm install -g harness-router harness-router configure harness-router doctor --live

configure detects your installed CLIs, verifies auth, and writes config. doctor --live validates the install and routes one real prompt end-to-end.

Then wire it into your agent by adding the MCP server to your agent config:

"mcpServers": { "harness-router": { "command": "harness-router" } }

The surface

Three ways to talk to it:

MCP

Tools: code, job, usage. Resources: harness-router://status.

REST

OpenAI-compatible: POST /v1/chat/completions, GET /v1/status.

Local endpoints

Direct routing to Ollama, LM Studio, vLLM, or any OpenAI-compatible server.

Policy

The routing policy is explicit about billing. Metered API routes (raw OpenAI, Anthropic, or unknown endpoints) are blocked by default. Routes that can incur overage (Claude Code, Codex, Cursor subscriptions) are blocked until you set allow_paid_usage: true on each one you trust.

This prevents accidental paid-API burns: if you don't understand the billing model of a route, it won't run until you explicitly allow it. Safety profiles (read_only, workspace_edit, full_auto) gate which harnesses can be used for sensitive work.

Positioning

What harness-router does and does not claim:

Category What it does What it does not
Agent CLIs Delegates to the agents you own, through their official interfaces. It is not a replacement coding agent.
Routing Scores by task type, live quota, billing, safety, and configured priority. It does not measure or claim token savings.
Protocols Exposes MCP (for agents) and OpenAI-compatible REST (for tools). A2A orchestration is out of scope.

FAQ

Why local only?

harness-router runs on your machine and routes to your configured agents. No data leaves your system except to the agents themselves. The only network call outside that is a public leaderboard GET for Arena ELO scoring.

Why require opt-in for paid routes?

If you don't explicitly set allow_paid_usage: true on a route, it won't run. This prevents accidents: you're forced to understand the billing model before spending money on that route.

What's the difference from 9router or other proxies?

Those tools are OpenAI-compatible proxies: they sit between your tool and the model, swapping models per request. harness-router swaps whole agents (Codex, Cursor, Claude Code) per task, so each agent keeps its own scaffolding and tooling. No MITM, no protocol spoofing.

Can I use it with an orchestrating agent?

Yes. Wire it into any MCP-capable orchestrator (Claude Code, Cline, etc.) and it becomes a delegation point. Your orchestrator calls the code or job tool with a prompt and task hint, harness-router picks the best route, delegates through the right agent's CLI, and returns the result.

Is it production-ready?

Yes. 259 tests pass, smoke tests pass, cross-platform (Windows/Mac/Linux). The API surface is small and stable. See GitHub for the full story.
