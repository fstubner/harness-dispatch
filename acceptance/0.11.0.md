Ten PRs on this line, all merged the day before the tag, so nothing in this

nobody had walked — a data-loss path, a credential path, and a class of guard
that lied about route names — rather than from re-reviewing familiar code.

## Open at ship time

New, and known:

- **The published tarball has never been run on macOS.** CI runs the symlink
  entrypoint test on `macos-latest` every PR and it passes, which covers the
  built file from a checkout. The packaged artifact on macOS is untested, on
  this release and every earlier one. The npm deprecation of `<0.9.0` names
  macOS on mechanism-based reasoning plus a measured Linux run, and says
  "(verified on Linux)" for that reason.
- **A permission-bit-only change under `copy` is not detected.** `chmod +x`
  with byte-identical contents is invisible, because changed files are compared
  by content hash and size. Documented in `docs/operations.md`. Detection alone
  would be worse than the gap: such a file would be reported as modified while
  contributing no patch section, which is the state `applyWorkspace` refuses —
  a silently dropped bit would become a refused apply.
- **A `model` naming no configured route is still routed leniently.** It is the
  OpenAI protocol's own field and clients fill it with placeholders; refusing
  it would break ordinary clients.
- **MCP-side `prompt` and `models` lengths are unbounded.** The HTTP surface is
  capped at `MAX_REQUEST_BODY_BYTES` (10 MB) with a clean 413; the MCP caller is
  local and uncapped. Deliberate — inventing a limit would be speculative.
- **Two prototype-chain sites were fixed without tests**
  (`http/server.ts`'s dispatcher filter, `mcp/config-hot-reload.ts`). Both take
  their names from config rather than a caller, so triggering them needs a route
  literally named `constructor` in `config.yaml`, and a test that cannot be
  shown failing against the old behaviour is not kept here.

Carried from 0.10.0, none re-verified for this release:

- MCP JSON-RPC error frames bypass the redaction sinks on the HTTP transport;
  covered on stdio by `installOutputRedaction`.
- `stream-subprocess` has no backpressure; past `maxBufferedChunks` the child is
  killed and the iterator rejects.
- Redaction is value-based, so an `api_key` that is an ordinary word mangles
  output wherever that word appears.
- `.supervisors/` still grows for non-empty spawn logs, deliberately.
- The Windows `workspace-resolve` git-spawn flake, roughly 1 full-suite run in
  11. Not diagnosed.
- 0.9.0's carried list, also not re-verified: breaker counts lost past ~24
  concurrent processes; `durationMs` excludes the response body read; a
  timeout-killed body read does not name the timeout; `fetch_benchmarks.py`
  cp1252 on Windows; a bare `HTTP/2 429`; the workspace marker file forgeable by
  a same-uid attacker; `apply`'s dirty-tree refusal exists only inside a git
  repo.

## Verified

- **One live dispatch, on this build.** `node dist/bin.js dispatch --service
  claude_code_cli --safety read_only --no-fallback "Reply with exactly one word:
  pong"` returned `pong`, exit 0, against the 0.11.0 artifact. First route
  attempted, no refusals. No metered route was touched and `--allow-paid` was
  not passed.
- `npm run check` on the tagged tree: 80 files, **1311 passed, 8 skipped**, both
  typechecks clean, `claims` exit 0.
- `npm run smoke` against this build: `harness-dispatch 0.11.0 smoke ok`,
  exit 0. This is the same step `publish.yml` runs as a release gate.
- `dist/bin.js --version` reports `0.11.0`, and `plugin.json` matches
  `package.json` — pinned by a test that exists because those two drifted
  across three minor versions before.
- **Published-artifact behaviour on real Linux** (WSL 2, kernel 6.18, Linux
  node v22.23.2, npm 10.9.8): published `0.8.0` invoked through a genuine
  `npm install -g` symlink exits 0 with **0 bytes** on stdout and stderr, while
  the same file by its real path prints 2510 bytes of help, and published
  `0.10.0` through the identical symlink prints 2510 bytes. This is the evidence
  behind deprecating `<0.9.0`.
- **macOS entrypoint coverage.** `tests/bin-entrypoint.test.ts` creates a real
  symlink named `harness-dispatch` pointing at the built `dist/bin.js` and
  spawns node through it — the exact npm global-install shape. It is skipped
  only on Windows, and the latest `macos-latest` CI job reports all 9 of that
  file's tests passing.
- **Every fix in this release was sabotage-checked individually**, each failing
  only its own cases: the prototype-chain guards (4 / 4 / 3 / 4 failures across
  four sites), the env-reference gate (4), the streamed chunk fields (1), chunk
  id stability under a per-frame id (1), and the workspace diagnostic (1). The
  router dispatcher guard is worth naming: reverting it was invisible to the
  entire suite until a test was written for it this cycle.
- **Package contents measured before and after**: 266 → 136 files, 2,003,218 →
  1,414,790 bytes unpacked, 562,042 → 452,421 packed, zero `.map` files, and no
  `sourceMappingURL` references remaining.
- **All 11 GitHub Actions pinned to commit SHAs**, each read from the upstream
  `tags/vN` ref, annotated tags dereferenced, and every SHA confirmed to exist
  as a commit in that same repository. GitHub's own Dependabot config check
  reported SUCCESS on five separate PRs.
- **`harness-dispatch@<0.9.0` deprecated on npm**: verified against the registry
  as 20 versions carrying the notice with 0.9.0 and 0.10.0 untouched, one
  distinct message, text intact.
