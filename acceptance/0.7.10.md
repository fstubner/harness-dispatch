  metered` becomes tier 3, `weight: very-high` becomes 1.0, `disabled:` as a

  and have silently been running at tier 3. **FIXED after the eighth pass (BUILDER; verified by the ninth)** for
  numeric and boolean fields — verified against that real config, which now
  names all four routes. `disabled:` written as a string, and `clis:`/
  `endpoints:` written as a map, remain silent and are still open.

  A delegate audit from the same pass also found the legacy `services:` shape
  getting NEITHER validator — both were wired into the two modern loops only, so
  a legacy config reported one warning where the modern shape reports four. The
  value check now runs there too. (The unknown-KEY check deliberately does not:
  the legacy shape accepts a wider set of keys, and reporting those as typos
  would be worse than the silence it replaces.)
- An empty HTTP 200 from an endpoint is reported as a SUCCESSFUL empty answer on
  the MCP surface and as a failure on the CLI. The buffered path guards on
  unextractable content; the streaming path treats zero parsed chunks with no
  stream error as success, and `jobs.ts` always uses the streaming path — so the
  MCP tool, which is the primary interface and the one an orchestrating agent
  branches on, is the one that gets it wrong. The breaker heals on it, so a route
  serving nothing but empty 200s never trips. Reproduced by the ninth pass.
  FIXED (BUILDER), after a first attempt that was wrong about its own premise.
  The tenth pass found the fix, its comment, the CHANGELOG and this entry all
  asserting that the buffered path already refused an empty answer — it did
  not. `#extractContent` returned any string, so a well-formed 200 with
  `content: ""` was a success with no output on the CLI path, measured as
  `dispatch` printing nothing and exiting 0. The claim had never been checked.
  Both paths now refuse it, verified in both directions rather than assumed in
  one. The tenth pass also found the new streaming error asserting "200 with no
  content" for bodies that DID carry content (an HTML error page, prose, and a
  gateway that ignored `stream: true`); it now names the body the way the
  buffered path does, while a genuinely empty SSE stream still reports no
  content. Sabotage-checked per guard.

  THIRD ATTEMPT, after the eleventh pass falsified the second. Guessing WHY a
  response was unusable was wrong three times in three different ways — the
  SSE test threw away a real answer arriving in another dialect, called a real
  provider's keepalives an unexpected shape, and classified the same body
  differently depending on how the network split it (the "bounded to 300
  characters" comment was false; it grew by whole chunks). The dispatcher no
  longer classifies: bytes arrived or they did not, and if they did they are
  quoted. The buffered path's dangling "Unexpected response shape: " for an
  empty body is gone too.

  The claim that the two paths therefore agreed was STILL not true, and the
  twelfth pass found the remaining case against a real socket: a server
  sending 200 plus a partial body and then resetting made the buffered path
  assert "the endpoint returned 200 with no body", while streaming reported
  "terminated" and kept the partial output. A failed read is not evidence of
  what the server sent. Both paths now call one shared function, so the
  agreement is enforced rather than claimed, and a failed read is reported as
  one. The message also no longer calls the shape unexpected — a stream that
  carried nothing had exactly the expected shape — and the CHANGELOG sentence
  asserting the previous version "cannot be wrong" is gone. Not re-verified by
  an independent pass.

## Verified

**Live dispatch (seventh pass).** `node dist/bin.js dispatch --service claude_code_cli --safety
read_only --no-fallback "Reply with exactly one word: pong"` → `pong`,
`success: true`, 6,779 ms, 48,007 input / 4 output tokens. Run against the build
in the working tree. No metered route, no `--allow-paid`, no `doctor --live`.

The pass also disclosed two unplanned live calls: a second `claude_code_cli` run
through the MCP `dispatch`→`job_status` path, and one accidental `codex_cli`
dispatch at `workspace_edit` caused by assuming `--config` replaces the shipped
routes. It does not — `clis:` entries are additive, and the only lever that
isolates you from your real routes is `disabled: [...]`. That is documented
behaviour and worth knowing before writing a throwaway config.

**The four fixes no earlier pass had seen**, all measured against `dist/`:

- HTTP streaming stops rather than falling back once answer text has been sent.
  A primary that streamed two fragments and then destroyed the socket produced
  both deltas, an error frame, and **zero** fallback route hits. A primary that
  failed *before* sending anything still fell back and delivered the fallback's
  full answer. Both directions correct.
- `connect --yes` refuses to overwrite a hand-edited entry, exit 1, file
  byte-identical; `--force` overrides while preserving the entry's `env` and
  unrelated servers, and takes a backup. Backup pruning holds at three.
- `git_worktree` unregisters and removes a worktree when an attempt failed and
  changed nothing, keeps one that changed files with a `cleanupHint`, and leaves
  `git worktree list` clean after a scored dispatch whose fallback arm also
  failed — the case that previously left two entries.
- The CHANGELOG's false claim that a server start drains the slot queue is gone.

**Suite.** `npm run check` clean: 71 files, 960 passed, 4 skipped, typecheck
clean, claims checker clean.

**Walkthrough.** Every step of `ux-walkthrough.md` happened as written: `status`
without a config file, `doctor`'s eleven named checks, exactly six MCP tools and
two resources, async dispatch returning `completed: false` plus a `jobId`,
`partialOutput` tailing a running job, `usage` counting the detached runner's
work, `job_status` with no id returning `{"jobs": []}`, the no-routes empty
state, and `cancel_job` moving a running job to `cancelled` within a second
while warning that changed files are not reverted.

**Changelog audit.** Every reachable claim in `[Unreleased]` was checked against
the artifact. Three problems were found and fixed after the pass: `GET /health`
and `OPERATIONS.md` were filed under `### Fixed` when both are additions, and
"2.7x the ceiling" was a composed figure (the numbers given yield 2.65x) in both
`CHANGELOG.md` and `config.default.yaml`. The machine-history numbers — 840
project directories, a month of dispatch logs, the 13,554 and 21,670-character
prompts — could not be re-verified from a checkout and are carried on the
record of the passes that measured them.

**Also confirmed:** `routing.candidates` now reaches `dispatches.jsonl` on
scored dispatches, which closes the one item 0.7.9 shipped open.

**Live dispatch (eighth pass).** The same one-liner on `claude_code_cli` →
`pong`, `success: true`, 10,279 ms, 48,804 input / 4 output tokens, logged with

**Quota accounting is exact.** Across 4 successes, 2 failures, 1 cancellation, 1

**Config error handling.** Malformed YAML, a missing `--config`, a route with no
