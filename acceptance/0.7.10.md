# Acceptance — 0.7.10

- version: 0.7.10
- verdict: CONDITIONAL
- date: 2026-08-29
- reviewer: independent agent pass, separate context from the build

Six passes ran during this cycle. Each reviewed a commit, found defects, and the
fixes landed after it — so for most of them the reviewed state was not the state
that would ship. This record is written from a seventh pass run against
`f564a10` specifically to close that gap: the release candidate itself, with the
last round of fixes already in it.

## Open at ship time

- `connect` can widen the permissions of `~/.claude.json`, a file holding live
  API keys. **Fixed after the pass** (`writeJsonAtomic` now carries the
  original's mode onto the replacement), but the fix is POSIX-only behaviour
  verified by reading rather than by running — this machine is Windows, where
  the mode does not apply. Unproven on the platform where it matters.
- The `git_worktree` failure cleanup swallowed a failed `git worktree remove`,
  deleted the directory anyway, and reported "unregistered and removed"
  regardless — stranding `.git/worktrees/<name>` in the user's repository, the
  outcome the surrounding code says it refuses to cause. **Fixed after the
  pass**: the directory is removed only if git released it first, and otherwise
  the worktree is reported like any other retained one.
- A config warning is reachable only from `doctor`. `dispatch` answers
  `Unknown service: <name>` and `status` shows a short route list, neither
  pointing at the diagnosis. The pass hit this twice by accident while writing
  a config, which is how a new user will hit it.
- A streamed request that falls back successfully still emits an SSE `error`
  frame for the failed attempt. A client treating `error` as terminal discards a
  good answer. Predates this cycle.
- Streaming creates no job record, so an interrupted stream cannot be recovered
  and there is no `jobId` to poll. Documented in `README.md` and
  `OPERATIONS.md`; not fixed, because routing streaming through the job system
  is a redesign rather than a fix.
- Telemetry spans are never flushed — `shutdownObservability()` is exported and
  called from nowhere — and OpenTelemetry's default process detector would carry
  argv, which for `dispatch "<prompt>"` contains the prompt. Off by default,
  behind an explicit opt-in, and documented as a known defect in
  `OPERATIONS.md`. The two must be fixed together: fixing the flush alone ships
  the leak.
- The test suite fails intermittently under load with resource-shaped errors
  (`spawn UNKNOWN`, a failed `git commit`, one "the paging file is too small"
  from a concurrent dispatch). Parallel process-spawning exhausting the machine
  rather than a logic race; three consecutive runs on an idle machine were
  green. `npm run check` is not a reliable gate on a busy machine.
- `PRODUCT.md` declares no provenance, so the acceptance gate's
  `A-intent-anchored` check is `not_evaluated` and SHIP is unreachable. This
  verdict covers consistency and build quality, not whether this is the right
  product.

## Verified

**Live dispatch.** `node dist/bin.js dispatch --service claude_code_cli --safety
read_only --no-fallback "Reply with exactly one word: pong"` → `pong`,
`success: true`, 6,779 ms, 48,007 input / 4 output tokens. Run against the build
in the working tree. No metered route, no `--allow-paid`, no `doctor --live`.

The pass also disclosed two unplanned live calls: a second `claude_code_cli` run
through the MCP `dispatch`→`job_status` path, and one accidental `codex_cli`
dispatch at `workspace_edit` caused by assuming `--config` replaces the shipped
routes. It does not — `clis:` entries are additive, and the only lever that
isolates you from your real routes is `disabled: [...]`. That is documented
behaviour and worth knowing before writing a throwaway config.

**The four fixes no earlier pass had seen**, all measured against `dist/`:

- HTTP streaming stops rather than falling back once answer text has been sent.
  A primary that streamed two fragments and then destroyed the socket produced
  both deltas, an error frame, and **zero** fallback route hits. A primary that
  failed *before* sending anything still fell back and delivered the fallback's
  full answer. Both directions correct.
- `connect --yes` refuses to overwrite a hand-edited entry, exit 1, file
  byte-identical; `--force` overrides while preserving the entry's `env` and
  unrelated servers, and takes a backup. Backup pruning holds at three.
- `git_worktree` unregisters and removes a worktree when an attempt failed and
  changed nothing, keeps one that changed files with a `cleanupHint`, and leaves
  `git worktree list` clean after a scored dispatch whose fallback arm also
  failed — the case that previously left two entries.
- The CHANGELOG's false claim that a server start drains the slot queue is gone.

**Suite.** `npm run check` clean: 71 files, 960 passed, 4 skipped, typecheck
clean, claims checker clean.

**Walkthrough.** Every step of `ux-walkthrough.md` happened as written: `status`
without a config file, `doctor`'s eleven named checks, exactly six MCP tools and
two resources, async dispatch returning `completed: false` plus a `jobId`,
`partialOutput` tailing a running job, `usage` counting the detached runner's
work, `job_status` with no id returning `{"jobs": []}`, the no-routes empty
state, and `cancel_job` moving a running job to `cancelled` within a second
while warning that changed files are not reverted.

**Changelog audit.** Every reachable claim in `[Unreleased]` was checked against
the artifact. Three problems were found and fixed after the pass: `GET /health`
and `OPERATIONS.md` were filed under `### Fixed` when both are additions, and
"2.7x the ceiling" was a composed figure (the numbers given yield 2.65x) in both
`CHANGELOG.md` and `config.default.yaml`. The machine-history numbers — 840
project directories, a month of dispatch logs, the 13,554 and 21,670-character
prompts — could not be re-verified from a checkout and are carried on the
record of the passes that measured them.

**Also confirmed:** `routing.candidates` now reaches `dispatches.jsonl` on
scored dispatches, which closes the one item 0.7.9 shipped open.
