## What was reviewed

Seven commits since `v0.7.8`. The pass ran the gate (SHIP on all three checks),
reproduced the baseline exactly — 871 passed, 4 skipped, typecheck clean,
claims check clean, `npm run check` exit 0, smoke ok — and then installed the
packed tarball into a clean project with `--omit=dev` and drove it from there.

`routing.candidates`, the newest and least-exercised change, was checked on
every path that produces a decision: scored, tier fallback, forced, explicit,
fanout arms, and an async job round-tripping through the on-disk job JSON. It
is present exactly where something was compared and absent where nothing was.
The cap loses nothing because `reason` still states the true count, and the
rounding loses nothing because the winner's `finalScore` is still reported
unrounded. No consumer breaks: there is no output schema, no test asserting an
exact key set, and the dispatch log copies named fields only. Sabotaging the
line that copies it into the response fails the test that covers it.

The previous pass's blocking finding is confirmed closed at the level a CI
script sees: `doctor` exits 0 both with git present and with git genuinely
removed from `PATH`, measured against the built `dist/`.

The claims checker was checked for self-serving exemptions by disabling its own
opt-out marker: all seven exemptions fired and every one is a deliberate
placeholder, none hides a stale reference. It still bites — a planted stale
path, a bogus hint key, a bogus routing key and a re-introduced `hints.service`
all fired, the last with the correct public-versus-internal diagnosis.

## Open, not blocking

- **The tier gate makes scoring inert on a single-member tier.** On the
  maintainer's real config every `taskType` resolves to the same route with one
  candidate, because tier is a hard gate and score only breaks ties within it.
  A consequence: `taskType: "local"` cannot reach a tier-3 local endpoint, so
  the schema's claim that it "prefers free local endpoints" is conditionally
  true at best. This predates these commits and is config-shaped — a machine
  with a tier-1 local endpoint behaves as documented. Fix the wording or the
  gate in 0.7.10.
- **The dispatch log records `reason` but not `candidates`.** The data that
  justified adding the field still cannot be analysed from logs.
- `routing.candidates` emits a one-entry list when the scored path had one
  eligible route. `reason` disambiguates ("tier 1 best (1 available)"), and
  "the field was one route wide" is real information, so this is defensible as
  written rather than a defect.

- The HTTP `/v1` surface was not exercised end to end — `candidates` reaching

- `retry_job` at runtime, `cancel_job`, the `workspace` tool's git diff/apply,
  and the plugin install scripts.
- One platform, one Node: Windows 11, Node 24.14.1. The `engines` floor of
  22.22.2 is untested here; CI covers Linux, macOS and the floor.
- The actual npm publish and OIDC trusted-publishing flow.
- Dependency vulnerability audit.
- Earlier passes' ground — command-line length measurement, npm-shim escaping,
  `modelHintDropped`, `resolveNamedRouteModel`, `MAX_TIMEOUT_MS`, the MCP/HTTP
  parity table, fanout `routePolicy`, workspace `copy` isolation — spot-checked
  via the passing suite only.
