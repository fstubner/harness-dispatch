- version: 0.10.0
- verdict: CONDITIONAL
- date: 2026-09-06
- reviewer: independent agent passes, separate context from the build. The
  final pass could not certify its own independence and said so; entries

Six independent passes ran on this line. Four of them returned BLOCK or NOT
CONFIRMED, every one on the same theme: a configured credential reaching a
caller, a log file, or an orchestrating agent's context. That defect was found
and "fixed" eight times at individual call sites before being closed
structurally — see the security entries in the changelog. A seventh pass, six
Haiku auditors with different lenses run in parallel, found three things the
credential-focused passes had walked past.

The final pass reviewed this release candidate and returned CONDITIONAL with
two HIGH documentation findings and five smaller ones. All seven were fixed
before the tag; those fixes are BUILDER and are listed below so the distinction
stays visible.

## Open at ship time

- **MCP JSON-RPC error frames bypass the redaction sinks on the HTTP
  transport.** Tool handlers throw, and the SDK serialises those errors
  straight to the socket rather than through `sendJson`/`writeSse`. Structural:
  no pass could construct a message carrying a configured credential, so this
  is a gap in coverage rather than a demonstrated disclosure. On stdio the
  frames are covered by `installOutputRedaction`.
- **`stream-subprocess` has no backpressure.** A consumer that stalls lets the
  internal queue grow, and past `maxBufferedChunks` the child is killed and the
  iterator rejects — turning a healthy run into a failure. Not reached at the
  shipped bound of 1000 in measurement. The module documents this honestly
  rather than claiming otherwise; fixing it is a real design change to the path
  every dispatch takes and was not attempted for this release.
- **Redaction is value-based, so a pathological `api_key` mangles output.** A
  key that is an ordinary word, or equal to the route's own model name, is
  removed from output wherever it appears. Correct behaviour for a value scrub,
  and worth knowing about.
- **`.supervisors/` still grows for NON-empty spawn logs.** The sweep added
  here removes only empty stale ones; a log with a crash reason in it is kept
  deliberately and forever.
- **The Windows `workspace-resolve` git-spawn flake.** `Error: spawn UNKNOWN`
  and `Command failed: git config user.email`, measured by one pass at roughly
  1 full-suite run in 11, 3 tests when it fires. The file passes 27/27 in
  isolation. Not diagnosed.
- Carried from 0.9.0, none re-verified here: breaker counts lost past ~24
  concurrent processes; `durationMs` excludes the response body read; a
  timeout-killed body read does not name the timeout; `fetch_benchmarks.py`
  cp1252 on Windows; a bare `HTTP/2 429`; the workspace marker file forgeable
  by a same-uid attacker; `apply`'s dirty-tree refusal exists only inside a git
  repo.

## Fixed after the final pass, by the builder, unreviewed

- The release notes declared `doctor --json` still printed text on a load
  failure. It does not; the same release fixed it (F1).
- PRs #223 and #224 had no changelog entries at all — eight user-visible
  changes, including `doctor` gaining a check that makes it exit 1 in an
  unbuilt checkout, and a lock sweep that now runs before every job start (F2).

  test; both were removed simultaneously and the suite stayed byte-identical at

  25ms against the acquire path's deliberate 1018ms grace — while its docblock,
  its commit message and its test all asserted the two used the same rule

- `--json` was honoured only for the exact token `--json`, and four error

  emit the envelope, and usage moved to stderr.
- The sink inventory omitted `result.md` and both `installOutputRedaction`
  calls; removing the first left the file 20/20 green (F7). All three added.

## Verified

- **One live dispatch, on this build.** `node dist/bin.js dispatch --service
  cursor_cli --safety read_only --no-fallback "Reply with exactly one word:
  pong"` returned `pong`. `codex_cli` refused first — usage limit until Sep 7 —
  which costs nothing and counts as a refusal, not a failure. No metered route
  was touched and `--allow-paid` was not passed.
- `npm run check` green in a single full run at the tagged tree: 80 files,
  **1269 passed, 8 skipped**, both typechecks clean, `claims` exit 0.
- The final pass independently ran the same gate at 4d48fd9: 1258 passed, 8
  skipped, exit 0, matching that commit's stated figure.
- Redaction verified at the built artifact against planted throwaway
  credentials on every CLI surface — `status`, `status --json`, `usage`,
  `usage --json`, `doctor`, `configure --print` — plus `logs/dispatches.jsonl`
  and the job directory after a real dispatch. Streamed and buffered HTTP
  responses both clean. A `${VAR}` on a non-credential field survives verbatim.
- Four of the eight redaction sinks are proven behaviourally: removing one
  fails that sink's case and no other. The other eleven have no reachable
  credential input today and are covered by an inventory that fails if the call
  disappears. Both facts are stated in the test file rather than implied.
- `doctor`'s job-runner check driven both ways at the binary: present → ok;
  `dist/job-runner.js` removed → fail, exit 1, correct under `--json`.
- CLI boundary: 14 adversarial invocations, all exit 1 with the path or the
  valid values named; no command exits 0 on an error. A directory as `--config`,
  `--config=` empty, missing file, invalid YAML with position, garbage
  `--safety`/`--task-type`.
- 0.9.0 findings 3 and 5 are closed, verified independently.
