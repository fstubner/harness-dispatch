## What was reviewed

tarball, `npm install --omit=dev` inside it (170 packages), and drive everything
from `dist/`. No evidence below comes from the source tree. No live provider

client SDK, so no quota was spent.

Gate: SHIP (`A-independent`, `A-product-contract`, `D-backend-engineering`, the
last re-run fresh). Baseline reproduced: 64 files, 862 passed, 4 skipped,
typecheck clean, `npm run smoke` ok.

`ux-walkthrough.md` was walked step by step against the running product — the
first time in this series that happened end to end. Every step behaved as
written, including the ones never previously exercised: the empty state
reproduced the walkthrough's sentence verbatim; six jobs at the shipped
concurrency default gave 4 running and 2 queued with `slotQueued` on the record
and not in the status string; two SEPARATE server processes sharing a
`workingDir` under `shared_locked` serialized (5.2s + 5.2s took 11.2s wall);
killing the server 1.5s into a 10s job left the job to finish and a fresh
server returned it by `jobId`.

The `copy` workspace loop — the area that broke four releases running — was run
live rather than read. A delegate created, modified, deleted and nested-created
files; the caller's tree was byte-identical afterwards; `diff` produced a
correct four-section patch; `apply` landed all four and left the untouched file
alone; re-applying refused instead of doing damage.

All three counter-signals PRODUCT.md names as evidence of failure are absent at
this commit, including the two highest-risk guarantees tested at runtime rather
than in the source.

## Open, not blocking

- **`git` is an undeclared runtime requirement for the `workspace` tool.**
  Without it on `PATH`, `diff`/`apply` fail with a raw `spawn git ENOENT`
  wrapped as `could not diff <file> for this workspace`. The dispatch itself
  succeeds and the isolated workspace is created correctly, and the response
  carries `workspaceRoot`, so the work is recoverable by hand. README states the
  requirements as Node plus a harness; git is not mentioned and `doctor` does
  not check for it. Fix: one `doctor` check plus a README line.
- **No `--version` flag.** `harness-dispatch --version` exits 1 with
  `unknown option`. MCP `serverInfo` does report the version, so the agent
  consumer can always see it; a human diagnosing an install cannot ask directly.

Two below the bar for a finding: a cancelled slot-queued job keeps
`slotQueued: true` on its record (cosmetic), and `publish.yml`'s verify job is
ubuntu-only while `ci.yml` covers ubuntu/macOS/Windows plus the Node 22 floor on
every push to `main` (missing redundancy, not a hole).

Stated plainly, because the verdict is only as good as its coverage.

- `doctor --live` and every real harness. Claude Code, Codex, Cursor and `agy`
  were never invoked.
- `npm i -g` from the registry — a sandbox `EPERM` on this machine blocked
  installing the tarball into a probe project, so prod deps were installed in
  place instead. Same shipped layout, but not npm's global bin linking.
- `npx harness-dispatch` — hangs under this machine's AppContainer sandbox.
- The actual publish: OIDC trusted publishing, provenance and the
  already-published skip guard were read, not run.
- The `git_worktree` workspace policy (`shared`, `shared_locked` and `copy` were
  driven live).
- Live endpoint routes and real rate-limit/breaker behaviour against a genuine
  429 — covered by the suite only.
- Symlink escape and the copy race — relied on their tests rather than
  reproducing them.
- Plugin install paths and the docs site.
- Non-Windows platforms. Everything here ran on Windows 11; CI's macOS and Linux
  legs are the only evidence for those.
- The eight prior passes' ground (command-line length measurement, npm-shim
  escaping, the drift test, `modelHintDropped`, `resolveNamedRouteModel`,
  `MAX_TIMEOUT_MS`, the MCP/HTTP parity table, `routePolicy` in fanout) was
  spot-checked only where it intersected the flows above. Nothing looked wrong.

A limit of the gate itself, not the product: only the backend-engineering domain
checker was registered and re-run. No architecture or frontend checker executed,
despite `ARCHITECTURE.md`, `design-direction.md` and `design-tokens.json` being
present.
